# Таблицы шахматного дневника по PGN

## 1. Назначение

Этот шаблон предназначен для последовательного анализа на трёх уровнях:

1. **Партия** — факты PGN, ключевые события, ошибки и сильные решения.
2. **Неделя** — повторяющиеся паттерны в сопоставимой группе партий.
3. **Цикл 2–4 недели** — проверка одной тренировочной гипотезы.

Главный принцип: **что произошло на доске ≠ почему игрок так сыграл ≠ чему следует тренироваться**.

Поэтому записи разделены на:

- **Факт** — непосредственно следует из PGN или позиции.
- **Вердикт Chess Vision** — результат эвристического анализа, а не объективная движковая оценка.
- **Гипотеза** — возможная причина или интерпретация, требующая подтверждения игроком.
- **Рекомендация** — тренировочное действие, выбранное по повторяющимся подтверждённым данным.

## 2. Что можно и нельзя заполнить автоматически

| Поле | По одному PGN | По серии PGN | Требует ответа игрока |
|---|:---:|:---:|:---:|
| Дата, цвет, результат, соперник, рейтинги, контроль | да | да | нет |
| Ходы SAN/UCI и FEN перед событием | да | да | нет |
| Ошибки, обнаруженные текущими правилами | да | да | иногда нужна ручная проверка |
| Чистые ходы и чистые партии | да | да | нет |
| Повторяющиеся категории и контексты | нет | да | иногда нужна ручная проверка |
| Достоверный цейтнот | только при наличии часов | да | нет |
| «Что я думал» | нет | нет | да |
| Причина: внимание, расчёт, знание, оценка, план | только как гипотеза | только как гипотеза | да |
| Сон, усталость, настроение, тильт | нет | нет | да |
| Выполнение упражнения вне партий | нет | нет | да |

Если PGN не содержит часов, нельзя автоматически утверждать, что ошибка вызвана цейтнотом. Если причина не подтверждена игроком, она записывается как `неизвестно` или `гипотеза`.

# ЧАСТЬ I. ЕДИНЫЙ СЛОВАРЬ

## 3. Статус вывода

| Статус | Значение |
|---|---|
| `подтверждено` | вывод проверен по позиции и последовательности ходов |
| `кандидат` | эвристика обнаружила событие, но возможна компенсация или иной ресурс |
| `нужна проверка` | без ручного разбора надёжный вывод невозможен |
| `неизвестно` | данных недостаточно |

## 4. Приоритетные категории Chess Vision

| Категория | Человекочитаемое название | Как использовать |
|---|---|---|
| `MATERIAL_BLUNDER` | грубая материальная ошибка | проверять первой |
| `IGNORED_MATE_THREAT` | проигнорирована существующая угроза мата | проверять первой |
| `ALLOWED_MATE_IN_ONE` | допущен мат в один | проверять первой |
| `IGNORED_MATERIAL_THREAT` | проигнорирована материальная угроза | обязательная ручная проверка |
| `DEFENSIVE_BREAKDOWN` | ухудшена защита собственной фигуры | обязательная ручная проверка; не считать чертой игрока автоматически |

## 5. Сильные события

| Категория | Значение |
|---|---|
| `TACTICAL_STRENGTH` | чистый ход с созданным шахом или сильной вилкой |
| `STABLE_PLAY` | чистые ходы без обнаруженных ошибок; это агрегат, а не отдельный мотив |
| `CREATED_CHECK` | создан шах |
| `STRONG_FORK` | создана сильная вилка |
| `COMPENSATED_RISK` | риск сопровождается наблюдаемой материальной компенсацией |
| `IMPROVEMENT` | локально улучшено состояние позиции |

## 6. Причины — только после подтверждения игроком

| Код | Причина | Контрольный вопрос |
|---|---|---|
| `ВН` | внимание | Я знал это, но не проверил? |
| `РС` | расчёт | Я видел идею, но оборвал вариант слишком рано? |
| `ОЦ` | оценка | Я рассчитал продолжение, но неверно оценил итог? |
| `ЗН` | знание | Мне не хватало конкретного правила, структуры или приёма? |
| `ВМ` | время | Решение было искажено реальным дефицитом времени? |
| `ПЛ` | план | В спокойной позиции я не понимал, что улучшать? |
| `РК` | сознательный риск | Я видел опасность и осознанно принял её? |
| `Н/Д` | неизвестно | По PGN причина не устанавливается |

## 7. Фазы и контексты

| Поле | Допустимые значения |
|---|---|
| Фаза | дебют / миттельшпиль / эндшпиль / переход |
| Характер позиции | атака / защита / равновесие / маневрирование / тактический кризис / вынужденный ответ |
| Состояние материала | перевес / равенство / дефицит / неизвестно |
| Состояние времени | нормально / мало времени / флаг / нет данных |
| Сторона события | игрок / соперник / обе стороны / нейтрально |

## 8. Правила метрик

Любая доля записывается как **процент и дробь**, например `75% (12/16)`.

- Нельзя смешивать bullet, blitz и rapid в одной динамике без отдельных строк.
- Желательно разделять платформы и резко разные рейтинговые диапазоны.
- Сравниваются равные периоды или равные по размеру окна.
- Сырые количества не доказывают прогресс, если число партий изменилось.
- Малые выборки помечаются как низкая уверенность.
- Недоступная метрика записывается как `н/д`, а не оценивается приблизительно.

- `recognition = замечено / возможностей`;

## 29. Что нужно передать вместе с PGN

Минимально:

1. точное имя игрока, как оно записано в `White` или `Black`;
2. PGN-файл или текст PGN;
3. цель: одна партия, неделя, сравнение периодов или тренировочный цикл;
4. период или правило группировки по неделям;
5. желательно: платформа и контроль, если заголовки PGN неполны.

Для нового тренировочного цикла дополнительно полезны:

- текущая гипотеза;
- выбранный ритуал;
- факт применения ритуала после каждой партии;
- состояние игрока, если нужно исследовать усталость или тильт.

## 30. Последовательность обработки

1. Разделить многоигровой PGN на отдельные партии.
2. Проверить UTF-8/BOM и корректность каждой партии.
3. Проверить точное совпадение имени игрока.
4. Зафиксировать дубликаты, пропуски и предупреждения.
5. Сохранить паспорт партии и временные данные.
6. Проанализировать только ходы выбранного игрока.
7. Для каждого важного события сохранить ход, SAN/UCI и FEN до хода.
8. Вручную проверить приоритетные события и обязательных кандидатов.
9. Пересчитать итог партии из строк событий.
10. Пересчитать недельные и цикловые агрегаты из строк партий.
11. Показать проценты только вместе с числителем и знаменателем.
12. Отделить подтверждённые выводы от гипотез и рекомендаций.

# ПРИЛОЖЕНИЕ A. Разбор позиций длинных размышлений (человеческий метод)

## A.1. Назначение

Позиции, перед которыми игрок думал дольше обычного и терял время, — отдельный тренировочный материал. Они уже оплачены временем и эмоциями, поэтому дают самую высокую отдачу на минуту разбора.

Источники позиций: список длинных пауз и истощающих обдумываний в журнале; FEN до хода сохранён автоматически.

## A.2. Почему без движка

Движок с глубиной 20 почти в любой позиции любителя найдёт перевес одной из сторон и скажет «сюда лучше было не попадать». Формально это честно, но:

- вердикт относится к позиции, а не к решению игрока;
- он не создаёт навыка — перманентный «минус» не тренирует;
- он обесценивает сам факт размышления: часто игрок думал над реальной проблемой, и это видно только без движковой оценки.

Chess Vision используется как источник наблюдаемых признаков — мотивы, угрозы, уязвимости, контроль полей, — а не как приговор.

## A.3. Вердикты

Один вердикт на позицию.

| Код | Вердикт | Смысл | Тренировочное действие |
|---|---|---|---|
| `ОД` | обоснованное обдумывание | позиция была критической или уникальной; простого решения не существовало | принять: время потрачено на реальную проблему; тренировать только скорость распознавания типа позиции |
| `ПС` | переизбыток поиска | был доступен простой ход: развитие, упрощение, защита слабости, размен | правило стабилизации: после долгой мысли — только простой ход |
| `ПР` | пропущенный человеческий ресурс | в позиции был распознаваемый мотив (вилка, связка, промежуточный ход, тактическая защита), который резко сузил бы поиск | тренировать именно этот мотив серией позиций |
| `ВП` | позиция уже хуже | выигрывать было нечего; правильная задача — спасение, упрощение, создание трудностей | принять факт и тренировать переключение «атака → защита» |

Вердикт «лучше было не попадать» допустим только как комментарий к `ВП`, но не как самостоятельный итог разбора.

## A.4. Правила разбора

1. Кандидаты — только ходы, которые игрок уровня ~1300–1500 реально находит за 20–30 секунд.
2. Каждый вердикт называет один-два конкретных кандидата и «первый вопрос», который сократил бы поиск (например: «есть ли у соперника шахи?»).
3. Запрещены оценки в пешках, centipawn, WDL и ссылки на движковые линии.
4. Исход партии после позиции ретроактивно не делает решение ошибкой: правильная идея при плохом исходе остаётся правильной идеей.
5. Chess Vision даёт признаки позиции; окончательный вердикт формулируется словами и подтверждается игроком.
6. Если позиция не поддаётся классификации — вердикт `н/д`, а не натянутый `ПР`.

## A.5. Формат записи

| Поле | Значение |
|---|---|
| Партия / ход |  |
| FEN до хода |  |
| Остаток времени / длительность мысли |  |
| Контекст Chess Vision | ситуация, мотивы, угрозы |
| Кандидаты уровня ~1400 | 1–2 хода |
| Первый вопрос | вопрос, сузивший бы поиск |
| Вердикт | `ОД` / `ПС` / `ПР` / `ВП` / `н/д` |

## A.6. Связь с дневником

- FENы берутся из журнала: длинные паузы, истощающие обдумывания, ходы перед подтверждёнными ошибками.
- Разбор вписывается в карточку партии одной строкой и в отдельный реестр разбора.
- Реестр разбора раз в цикл проверяется на повторяемость: если один и тот же вердикт встречается три и более раз — это кандидат в узкое место следующего цикла.
- Распределение вердиктов само по себе диагностика: преобладание `ПС` — проблема управления поиском; `ПР` — конкретный мотивный дефицит; `ОД` — игрок чаще прав, чем кажется, и тренировать надо скорость; `ВП` — проблема более ранняя, на этапе попадания в позиции.
